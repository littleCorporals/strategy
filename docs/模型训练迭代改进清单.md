# 模型训练迭代改进清单

更新时间：2026-06-08

## 目标

把当前模型从“能给候选”改进到“可作为复盘和操作前参考”。这里的“到位”不是追求单次高命中，而是建立一套持续可验证、可回滚、能解释失败原因的训练迭代闭环。

当前主线判断：

- 原始模型 TopN 不能直接作为买入候选，必须经过风险过滤和 T+1 交易约束。
- `next_high_3pct_v1` 只预测“次日最高价是否冲到 3%”，不等同于收盘盈利。
- 当前训练数据窗口仍偏短，资金、估值、行业、市场环境特征还没有完整纳入。
- 评估必须优先看 Top20/Top50/Top100 排序效果、真实预测验证和回撤风险，不能只看 Accuracy。

## P0：必须先补齐

### 1. 数据覆盖和训练样本质量

- [ ] 回填至少 240 个完整交易日的全市场 `daily`，优先目标为 1 年。
- [ ] 回填同区间 `daily_basic`，覆盖换手率、量比、市值、估值等字段。
- [ ] 回填可用的 `moneyflow`，先覆盖最近 60 个完整交易日，再扩到 240 日。
- [ ] 固化股票池过滤：剔除北交所、ST、退市、U/W、高风险或行情不可用股票。
- [ ] 训练、预测、实时筛选使用同一套股票池过滤规则，避免训练里学到不可交易样本。
- [ ] 生成数据覆盖报告：按接口展示交易日数、股票数、缺失率、最新日期。

验收标准：

- `daily` 最近 240 个交易日覆盖率可查。
- `daily_basic` 覆盖率不低于 95%。
- 训练样本中不再出现退市、ST、北交所和无法实时报价股票。
- 主看盘台和模型后台能显示本次训练的数据覆盖摘要。

### 2. 标签从“冲高”升级为“可交易”

- [x] 保留 `next_high_3pct_v1` 作为冲高标签，但不能单独决定候选。
- [x] 新增 `next_high_3pct_no_deep_drawdown_v1`：次日最高涨到 3%，且次日最低回撤不超过阈值。
- [x] 新增 `next_close_positive_v1`：次日收盘相对信号日收盘为正。
- [x] 新增 `next_low_drawdown_3pct_v1`：次日最低跌幅超过 3%，作为风险标签。
- [x] 新增 `next_open_gap_down_2pct_v1`：次日低开超过 2%，作为 T+1 风险标签。
- [ ] 模型尾盘候选展示时同时显示“机会分”和“风险分”，而不是只显示一个概率。

验收标准：

- 标签构造有单元测试覆盖。
- 模型后台能同时训练机会模型和风险模型。
- 主看盘台候选行能看到冲高概率、回撤风险、低开风险。

### 3. 评估方式改成滚动验证

- [ ] 增加 walk-forward 滚动验证：例如训练 120 日、验证后 5 日，滚动至少 20 个窗口。
- [ ] 每个模型保存滚动验证报告：Top20/50/100 命中率、市场基准、lift、平均收盘收益、平均最高收益、最大回撤。
- [ ] 候选模型必须与当前激活模型在同一验证区间对比。
- [ ] 模型后台增加“当前模型 vs 候选模型”对比页。
- [ ] 主看盘台模型卡显示最近 20 个可验证交易日的 Top50 均值和稳定性，而不是只显示单次验证。

验收标准：

- 至少 20 个可验证交易日的滚动结果入库。
- 新模型只有在同区间 Top50 lift、平均收盘收益或回撤风险不劣化时才允许上线。
- 单日 Top50 高命中不能直接触发上线。

### 4. 上线门槛和自动拦截

- [ ] 激活模型前检查验证样本数、Top50 lift、最近真实验证、拟合差。
- [ ] 如果验证样本太少、拟合差过大、真实验证低于基准，禁止一键上线。
- [ ] 每次生成预测后自动验证最近可验证日期，更新模型健康状态。
- [ ] 模型健康状态低于阈值时，主看盘台只显示“观察”，不显示“候选”。
- [ ] 所有拦截原因写入 `ml_model_events`。

验收标准：

- 不满足门槛的模型无法激活。
- 主看盘台能明确显示“模型可信度不足”的原因。
- 回滚路径可用，且回滚事件可审计。

## P1：提升模型有效性

### 5. 特征集升级到 `short_swing_v3`

- [ ] 纳入 `daily_basic`：换手率、自由换手率、量比、市值、PE、PB。
- [ ] 纳入 `moneyflow`：主力净流入、超大单、大单、中单、小单结构。
- [ ] 纳入股票属性：行业、上市年限、流通市值分层。
- [ ] 纳入行业强弱：行业当日涨幅、行业上涨占比、行业成交额排名。
- [ ] 纳入市场环境：全市场上涨占比、平均涨跌幅、成交额、强弱温度。
- [ ] 纳入风险特征：近 5/10/20 日最大回撤、长上影、跳空、振幅分位。
- [ ] 固化特征版本，保存每个模型的特征列表和缺失率。

验收标准：

- `short_swing_v3` 特征数量、缺失率、Top 权重可在模型指标页查看。
- 特征构造严格只使用信号日前及当日可得数据。
- 新特征集与 `short_swing_v2` 在同区间对比后再决定是否上线。

### 6. 模型从基线升级为表格模型

- [ ] 保留 `logistic_ranker_v1` 作为可解释基线。
- [ ] 新增 `tree_ranker_v1`，优先使用 LightGBM 或 XGBoost；如环境未安装，先用 sklearn 梯度提升树。
- [ ] 增加概率校准，避免 0.99 这种概率被误解为真实胜率。
- [ ] 输出特征重要性、候选解释、风险贡献。
- [ ] 同一标签、同一训练窗口下比较线性模型和树模型。

验收标准：

- 新模型必须在滚动验证中优于基线，才允许成为候选。
- 概率显示改为“模型分/分位/校准概率”，避免误导。
- 任何模型都必须保留 artifact、参数、指标和训练报告。

### 7. 多模型组合

- [ ] 拆分机会模型：预测冲高或多日冲高。
- [ ] 拆分风险模型：预测低开、大跌、深回撤。
- [ ] 拆分流动性模型：预测成交额是否足够支撑交易。
- [ ] 最终候选排序使用组合分：机会分 - 风险分 + 流动性分 + 实时承接分。
- [ ] 候选列表显示组合分拆解。

验收标准：

- 候选行能看到机会、风险、流动性、实时承接四个分项。
- 单一机会模型高分但风险模型高危时，自动降级或剔除。

## P2：运行和监控闭环

### 8. 日常自动流水线

- [ ] 收盘后自动刷新行情缓存。
- [ ] 自动生成最新交易日预测。
- [ ] 自动验证最近可验证预测。
- [ ] 自动更新模型健康状态。
- [ ] 失败任务自动记录错误、支持重试。

验收标准：

- 每天打开页面前，预测和验证状态已经可见。
- 手工点击只作为补救，不作为日常依赖。

### 9. 前端操作参考增强

- [ ] 候选列表支持按模型分、风险分、成交额、行业、涨跌幅筛选排序。
- [ ] 每只股票详情增加模型解释：为什么入选、为什么剔除、风险来自哪里。
- [ ] 候选列表显示同板块候选数量和板块强弱。
- [ ] 显示原始模型 TopN 与实时过滤后的差异，便于复盘模型失误。
- [ ] 增加“只看低风险”“只看强承接”“只看行业集中”模式。

验收标准：

- 用户不需要去后台，也能判断模型版本、命中、拟合、分数和风险。
- 每只候选股票都有可复核的入选理由和放弃理由。

### 10. 风控和复盘

- [ ] 每日生成候选复盘：入选、剔除、次日结果、错误类型。
- [ ] 统计模型常见失败原因：高开低走、低开、冲高回落、板块退潮、流动性不足。
- [ ] 对失败原因反向增加标签或特征。
- [ ] 建立模型降级规则：连续 N 天 Top50 低于市场基准时停止推荐。

验收标准：

- 每次坏结果都能归类，不再只看到“跌了”。
- 失败归因能进入下一轮训练任务。

## 执行顺序

1. P0-1 数据覆盖和股票池过滤。
2. P0-2 可交易标签和风险标签。
3. P0-3 滚动验证和模型对比报告。
4. P0-4 上线门槛和自动拦截。
5. P1-5 `short_swing_v3` 特征。
6. P1-6 表格模型。
7. P1-7 多模型组合。
8. P2-8 自动流水线。
9. P2-9 前端操作参考增强。
10. P2-10 风控复盘。

## 当前不得跳过的硬规则

- 不允许把原始模型 TopN 当候选。
- 不允许只看 Accuracy 判断模型好坏。
- 不允许只用单日验证结果上线。
- 不允许训练集和验证集随机混洗。
- 不允许使用预测日之后的数据构造特征。
- 不允许在 T+1 场景下对高位过热票给出新开候选。
- 不允许没有验证报告就替换激活模型。
