# 改造进度清单

更新时间：2026-05-29

## 目标

把当前股票决策台从可运行 MVP 改造成可长期扩展的标准工程：业务、数据、第三方客户端、模型工程、模型管理后台分层清晰，后续可以平滑接入训练流水线、模型版本上线/下线、每日推理和次日验证。

## 架构原则

- `app/main.py` 只负责应用装配，不承载业务逻辑。
- `app/api/routes/` 只处理 HTTP 入参和出参，业务计算逐步下沉到 `app/services/`。
- `app/clients/` 只放第三方服务适配器，包括 Tushare、巨潮资讯、AI 接口。
- `app/repositories/` 只放数据访问和缓存仓储，避免路由层直接散落 SQL/缓存策略。
- `modeling/` 只放模型工程能力，不反向依赖 `app`。
- 所有模型版本、训练任务、推理结果、验证结果必须入库，可追溯、可回滚。

## 当前风险

- `app/api/routes/market.py` 已降到约 426 行，但仍保留少量兼容包装函数，后续可继续收敛到纯路由层。
- 个股分析已区分 `requested_end_date` 和 `actual_trade_date`，前端仍可进一步展示“已回退到实际行情日”的提示。
- migrations 目前是 MVP，只有前向 SQL 执行和版本记录，暂未提供回滚、校验和复杂数据迁移模板。
- 模型生命周期已有注册、审批、拒绝、激活、下线、归档、审计、回滚和效果监控 MVP，但还没有灰度策略、权限控制和自动告警。
- 模型训练流水线目前是轻量基线模型，尚未接入 XGBoost/LSTM/Transformer 等真实训练框架和模型解释报告。
- 每日推理和次日验证已有 MVP，但尚未接入定时任务、失败重试、监控告警和前端效果曲线。
- 模型后台已改为左侧菜单、右侧内容的管理系统布局，但仍可继续补图表化表现曲线、权限控制和更明确的风险提示。
- 主看盘台已改为后台管理系统布局，后续可继续补充表格排序、字段筛选、模型预测解释曲线和键盘快捷筛选。
- 管理接口已限制本机访问并支持可选 `ADMIN_TOKEN`，但尚未做完整用户体系；如未来部署到局域网或公网，需要补登录、权限和 CSRF 策略。
- 自动化测试已覆盖核心入口、生命周期 API、训练流水线、每日推理和次日验证 MVP。
